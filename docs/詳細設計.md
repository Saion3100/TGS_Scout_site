
## 2. システム構成・ディレクトリ構造

学校のレンタルサーバー（PHP環境）に最適化した構成です。

```
/ (root)
├── index.php              # トップページ（作品・学生への導線）
├── teams.php              # 全チーム一覧
├── team_detail.php        # チーム詳細（QR遷移先・メンバー一覧）
├── students.php           # 全学生一覧（職種・技術での絞り込み）
├── student_detail.php     # 個人プロフィール（制作物プレビュー）
├── contact.php            # 問い合わせフォーム（UIのみ）
├── assets/
│   ├── css/               # 白・赤基調のスタイルシート
│   ├── js/                # 検索フィルタリング、動画制御
│   └── img/               # 共通ロゴ、バナー等
├── data/
│   ├── students.json      # 学生データ（JSON）
│   ├── teams.json         # チーム・作品データ（JSON）
│   └── mapping.json       # チームと学生の紐付けデータ
└── includes/
    ├── header.php         # 共通ヘッダー
    └── footer.php         # 共通フッター
```

## 3. データ構造設計（JSON）

### 3.1 `students.json` (学生基本情報)

```json
{
  "id": "1",
  "name": "国際 太郎",
  "name_kana": "こくさい たろう",
  "name_en": "Taro Kokusai",
  "graduation_year": "2027年卒",
  "course": "ゲームプログラマコース",
  "desired_roles": ["ゲームプログラマー"],
  "role": "プログラマー",
  "headline": "遊びの手触りを、コードで磨く。",
  "bio": "得意分野や制作姿勢を記載します。",
  "skills": ["C++", "DirectX12", "HLSL"],
  "fields": ["ゲームプレイ", "グラフィックス"],
  "interview_available": true,
  "internship_interest": true,
  "portfolio_url": "https://drive.google.com/file/d/FILE_ID/view",
  "source_code_url": "",
  "video_url": "https://www.youtube.com/embed/VIDEO_ID",
  "is_active": true
}
```

#### 入力ルール

- 全学生で上記のキーと順序を共通化します。値がない文字列は `""`、リストは `[]` を入力します。
- `id` はサイト内で重複しない `s` + 3桁の連番とし、公開後は変更しません。
- `role` は画面の職種フィルターに表示する日本語名です。同じ職種では表記を統一します。
- `graduation_year` は `2027年卒` の形式で入力します。学年は毎年の更新が必要になるため保持しません。
- `desired_roles`、`skills`、`fields` は、1項目ずつJSON配列に分けます。
- `interview_available`、`internship_interest`、`is_active` は文字列ではなく `true` / `false` を使用します。本番公開前の学生は `is_active` を `false` にします。
- Google DriveのPDFを埋め込む場合、`portfolio_url` にファイルURL全体を入力します。閲覧権限は「リンクを知っている全員」に設定します。
- VIVIVITや企画書などの作品ページも `portfolio_url` に統合し、プログラマーのコードだけ `source_code_url` に入力します。
- YouTube動画は通常の視聴URLではなく `https://www.youtube.com/embed/VIDEO_ID` 形式を使用します。

### 3.2 `featured_students.json`（トップページ注目学生）

```json
{
  "student_id": "2",
  "order": 1,
  "focus": "世界観を伝えるビジュアル設計",
  "teacher_comment": "教員コメントを記載します。"
}
```

学生本人から収集する情報と分離し、トップページに掲載する学生だけを登録します。`student_id` は `students.json` の `id` と一致させ、`order` は重複しない整数にします。

### 3.3 `teams.json` (作品情報)

```
{
  "id": "t01",
  "game_name": "スライムバスターズ",
  "booth_no": "09-C01",
  "description": "作品の概要・注目ポイント...",
  "thumbnail": "path/to/img.jpg"
}
```

## 4. 画面詳細・ロジック設計

### 4.1 チーム詳細ページ（QR遷移先）

- **機能**: 各試遊台のQRコード（`team_detail.php?id=t01&src=tgs_booth`）から直接流入。
- **表示**: `teams.json`から作品情報を、`mapping.json`を介して所属メンバーを抽出。
- **レイアウト**: メンバーを「プログラマー」「デザイナー」「プランナー」といった職種別にグループ分けして表示します。

### 4.2 個人プロフィールページ

- **PDFプレビュー**: Google Driveのプレビュー用URL（`https://drive.google.com/file/d/{ID}/preview`）を `<iframe>` で埋め込み、1ページ目がサイト上で直接見えるようにします。
- **動画再生**: ゲーム紹介動画（約1分程度）を埋め込み、技術力のフックとします。

### 4.3 問い合わせフォーム（UIのみ）

- **選択アクション**: 以下の5種類を選択肢（ラジオボタン等）として実装します。
    1. 学校の先生に連絡したい
    2. 説明会の相談をしたい
    3. この学生と話をしたい
    4. この学生に応募してほしい
    5. この学生に注目している
- **自動設定**: 遷移元の学生名またはチーム名をフォーム内に自動補完します。

## 5. UI・デザイン仕様

- **カラー**: 背景 `#FFFFFF`（白）、アクセント `#E60012`（赤）。
- **モバイル対応**: 閲覧の主軸はPC（会社での比較検討用）としつつ、会場でのスマホ閲覧でもレイアウトが崩れないレスポンシブ設計を徹底します。
- **タップ範囲**: モバイル操作を考慮し、ボタンやリンクのタップ範囲を44px以上確保します。

---

## 6. 非機能要件

- **検索エンジン拒否**: 採用関係者限定とするため、全ページに `noindex` を設定します。
- **表示速度**: 画像の遅延読み込み（`loading="lazy"`）や軽量なJSON読み込みにより、初期表示3秒以内を目指します。
- **セキュリティ**: 問い合わせフォームの入力値に対してPHPの `htmlspecialchars()` を適用し、XSSを防止します。
