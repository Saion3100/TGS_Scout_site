# 学生プロフィール写真のアップロード仕様

## 目的・対象

管理画面の学生タブで写真を選択し、横3：縦4に切り抜いて、学生情報と同時に保存する。
本番・試験とも組織の共有ドライブを使用する。マイドライブのOAuth認証は対象外。
参考：`image-upload-site`　
            `https://r1u2.v2011.coreserver.jp/it-work/TGS_Profile/`
参考の操作フローを採用し、外部ライブラリ不要のCanvasとスライダーで実装する。

## 画像と操作

- JPEG・PNG・WebP、元画像10MB以下、4000万画素以下。固定ピクセル数の入力条件は設けない。
- 横3：縦4。保存画像は最大横1200×縦1600、小さい画像は拡大しない。
- 縦横比を厳密に保つため、横3・縦4の整数倍へ丸める。
- 拡大率・左右・上下位置を調整し、確定後に掲載同意を確認して学生フォームを送信する。
- 調整し直した場合は再確定が必要。取り消すと既存写真を維持する。
- 透過部分は白背景。ブラウザーとPHPでJPEG化し、PHPで寸法・容量・実画像を検証する。
- 保存するのは加工済み画像のみ。後日の再トリミングには元画像の再選択が必要。

## 保存・参照

保存先既定値：`1nou3qIrmoeUR1LXg4SCJciLevDG_0K3m`。
APIでフォルダ形式・共有ドライブ所属・追加権限を確認してからmultipart uploadする。
名前は `student-{学生ID}-{ランダム文字列}.jpg`。既存ファイルの上書きは行わない。
新規アップロードにDriveのappPropertiesで `tgs_photo=v1` と `student_id` を記録する。
新写真の保存と学生JSON更新が両方成功した後、旧photo_drive_file_idの写真をゴミ箱へ移す。
対象は管理情報と学生IDが一致し、指定保存先フォルダ内にあるJPEGのみ。他学生の参照が残る画像は対象外。
もともとフォルダにあった写真、管理情報導入前のアップロード画像、他フォルダへ移動した画像は保持する。
ファイル名からの推定や一括整理は行わない。完全削除APIは使用しない。
JSONの `photo_drive_file_id` に返却IDを保存し、`photo_url` にサイト内画像URLを保存する。
`student_photo.php?id={学生ID}` は現在のIDからDrive画像を取得する。Driveのパス・ファイル名変更に依存しない。
公開学生のみ匿名表示可能。非公開学生は管理者セッションがある場合だけ表示する。
リクエストからDriveファイルIDを直接受け取らず、学生JSONを参照する。
Google認証情報をブラウザーへ渡さず、Driveの共有権限を一般公開へ変更しない。
新写真未選択の場合は既存のphoto_url・icon_urlとその他の学生項目を保持する。
既存写真の自動探索・氏名による自動紐付けは対象外。従来のURLは引き続き使用する。

## 失敗と制限

- Drive保存失敗時は学生JSONを更新せず、フォームにエラー表示。再送には写真の再選択が必要。
- Drive保存成功後にJSON保存が失敗すると、未参照の新ファイルが残り得る。旧参照は保持され、自動削除は行わない。
- 通信タイムアウト時も未参照ファイルが残る可能性がある。保存は自動再試行しない。
- 旧写真の整理に失敗しても新写真とJSON更新は維持し、管理画面に警告を出してサーバーログへ記録する。自動再試行はしない。
- 公開画像の取得失敗は502、対象なし・公開不可は404。
- 初期実装はキャッシュなし・no-store。毎回公開状態を確認する。アクセス増加時は公開判定後のサーバーキャッシュを別途検討する。
- 公開画面の既存表示枠も横3：縦4へ合わせる。

## 環境設定

PHP 7.4以上、GD（JPEG対応）・cURL・OpenSSLが必要。
Google CloudでDrive APIを有効化し、サービスアカウントを作成する。
保存先に追加・閲覧・ゴミ箱へ移動できる権限（共有ドライブのコンテンツ管理者相当）を付与する。実際の可否はAPIのcanTrashで確認する。投稿者権限のみでは自動整理できない場合がある。組織ポリシーによって管理者対応が必要。
サービスアカウントJSON鍵は公開ディレクトリ外・Git管理外に置き、PHP実行ユーザーだけが読めるようにする。

```dotenv
TGS_GOOGLE_CREDENTIALS=/absolute/private/path/service-account.json
TGS_GOOGLE_PHOTO_FOLDER_ID=1nou3qIrmoeUR1LXg4SCJciLevDG_0K3m
```

ローカルは既存の.env読込を使用。本番は環境変数または既存運用の非公開.envに設定する。
`upload_max_filesize=10M`、`post_max_size=12M`以上を目安に設定する。
外部HTTPS接続先は `oauth2.googleapis.com` と `www.googleapis.com`。TLS検証は無効化しない。
アクセストークンはRS256署名のサービスアカウントJWTで取得。スコープはdrive。
既存写真参照も想定したスコープのため、サービスアカウント自体のアクセス範囲を必要なフォルダに限定する。

## 検証

ローカル：PHP構文、JS構文、3:4出力寸法・縮小のみの計算、写真URL生成・既存URL互換を確認する。
設定後：管理者で新規・既存学生にアップロード、同意未確認、未確定、キャンセル、再調整、非画像、容量超過を確認する。
実接続：共有ドライブの新ファイル、既存ファイル維持、JSONのID一致、公開一覧・詳細表示、非公開写真の匿名404を確認する。
自動整理：新規アップロードを再度差し替えると旧画像だけがゴミ箱に移ること、管理情報なし・学生ID不一致・別フォルダ・他学生参照中の写真は維持されることを確認する。canTrashがない場合は新画像保存を維持して警告を表示する。
障害：誤った鍵・フォルダ・権限・通信失敗時に既存参照が変わらないことを確認する。
