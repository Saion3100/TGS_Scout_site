# adminページ仕様書

作成日：2026年9月10日  
対象：TGS SCOUT 管理画面

## 1. 目的・実装状況

学生・作品などの公開サイト用データを管理する。管理者は全体を管理し、学生はログイン時に選択した学生のプロフィールと、その学生が参加した作品だけを編集する。

本書は、既存機能と2026年9月10日に追加実装した学生ログイン・権限制御をまとめる。DBは使用せず、既存のJSONファイルによるデータ管理を継続する。

| 区分 | 状況 |
| --- | --- |
| 管理者用パスワードでのログイン | 実装済み |
| 学生・作品の登録編集、写真、QRコード | 実装済み |
| 注目学生・出展作品・参加メンバー管理 | 実装済み |
| 学生IDまたは氏名＋学生用共通パスワードでのログイン | 実装済み |
| ロールと学生IDに基づく編集範囲の制限 | 実装済み |

当初の文書作成後、実装依頼に基づき追加機能を実装した。公開状態は管理者限定、非公開学生もログイン可能とする方針を採用した。

## 3. 既存のログイン・共通機能

- 管理者はID欄に `admin`、パスワード欄に管理者用パスワードを入力してログインする。
- パスワードは環境変数 `TGS_ADMIN_PASSWORD` と照合する。未設定時は管理画面を利用できず、設定不足を表示する。
- ログイン成功時にセッションIDを再生成し、管理者認証状態とCSRFトークンをセッションに保存する。
- 未認証で管理ページにアクセスした場合、ログイン画面へ誘導する。
- ログアウト時にセッションを破棄し、ログイン画面へ戻る。
- 管理タブは「学生」「注目学生」「作品」「出展作品」。公開ページへ戻るリンク、ログアウト、ページ先頭へ戻る操作を備える。
- 一覧から対象を選び、編集フォームで保存する。未選択時は選択を促す表示を行う。
- 保存成功時はリダイレクト後に完了通知を表示する。入力不備はフォームにエラーを表示する。
- データ更新処理でCSRFトークンを検証する。不正なトークンは403のエラー処理へ送る。
- 想定外の例外はサーバーログへ記録し、500のエラー処理へ送る。
- 管理画面はHTTPヘッダー・HTMLメタ情報で検索エンジンの登録・追跡・アーカイブを抑止する。

追加前は管理者認証済みかどうかだけで判定していた。現在は `src/AdminAuth.php` で管理者と学生を区別する。

## 4. 既存の学生管理

### 4.1 一覧・登録・編集

- 登録件数、学生ID、氏名、職種、公開・非公開状態を表示する。
- ID昇順、名前昇順（ふりがな優先）で並べ替える。並び順はブラウザーに保存する。
- ID・名前・ふりがなで検索する。表記の全角半角、英字の大小、カタカナ・ひらがな、空白を正規化して検索する。
- 新規登録と既存学生の編集を行う。新規IDは既存の数値IDの最大値に1を加えて採番する。
- 既存学生のIDは編集対象を識別する固定値であり、入力欄から変更しない。
- 学生データそのものを削除する機能は実装されていない。

### 4.2 入力項目

| 分類 | 項目 | 条件 |
| --- | --- | --- |
| 基本情報 | 氏名、ふりがな、英字氏名、卒業予定年、コース | 必須 |
| 職種 | 職種 | 複数選択可・1つ以上必須 |
| 職種 | 希望職種 | 任意・複数入力可 |
| 紹介 | 見出し、プロフィール | 必須 |
| スキル | 使用技術・ツール、専門分野 | 任意・複数入力可 |
| 資料 | ポートフォリオ（Drive）、ポートフォリオ（外部サイト）、ソースコード（外部サイト）、公開可能な作品、ソースコード（Drive）のURL | 任意 |
| 動画 | 動画URL | 任意 |
| 活動設定 | 面談可能、インターン希望 | チェックボックス |
| 公開設定 | プロフィールを公開（`is_active`） | チェックボックス |
| 写真 | プロフィール写真 | 任意・詳細は次項 |

卒業予定年・コースの候補は既存学生データから取得する。リスト項目は改行・カンマ・読点で分割し、空欄や重複を取り除く。URLは入力がある場合、`http://` または `https://` から始まる有効なURLであることを検証する。

保存すると学生JSONを更新し、公開状態に応じて公開サイトへ反映する。編集フォームの対象外の既存データは保持する。

### 4.3 プロフィール写真

- JPEG・PNG・WebPを選択し、横3：縦4で切り抜く。元画像は10MB以下・4000万画素以下。
- 拡大率・左右位置・上下位置を調整し、切り抜きを確定する。再調整時は再確定が必要。
- 写真掲載への同意確認後、学生情報と同時に保存する。
- 保存画像はJPEG、最大1200×1600。小さい画像は拡大しない。
- 変更の取り消し、写真未選択時は既存写真を維持する。
- Google共有ドライブに加工後の画像を保存し、学生JSONにDriveファイルIDとサイト内の画像URLを保存する。
- 新写真とJSONの保存後、条件を満たす旧管理画像だけをゴミ箱へ移す。旧画像整理に失敗しても新しい保存結果は維持し、警告する。
- 写真設定不足時はファイル選択を無効化し、理由を表示する。
- 公開写真は匿名で閲覧できる。非公開写真は管理者、または該当学生としてログイン中の場合だけ閲覧できる。

保存失敗時の挙動、外部接続・環境設定の詳細は[学生プロフィール写真仕様書](学生プロフィール写真仕様書.md)を参照する。

### 4.4 プロフィールQRコード

- 学生保存時に `student-{学生ID}` のQR管理データを同期する。
- 学生の公開状態に合わせてQRコードの有効状態を更新する。
- 登録済み・公開中の学生に固定URL、QRプレビュー、PNGダウンロード、印刷操作を表示する。
- プロフィール内容を変更しても固定URLは変わらず、再印刷は不要。

## 5. 既存の作品管理

### 5.1 一覧・登録・編集

- 登録件数、作品ID、作品名、チーム名を表示する。
- ID昇順・作品名昇順で並べ替える。並び順はブラウザーに保存する。
- ID・作品名・チーム名で検索する。
- 新規登録と編集を行う。IDは既存の `t`＋数値IDの最大番号に1を加え、数値部分を最低2桁として採番する。
- 作品データそのものの削除や、作品の公開・非公開を切り替える専用機能は実装されていない。

### 5.2 入力項目

| 分類 | 項目 | 条件 |
| --- | --- | --- |
| 基本情報 | 作品名、チーム名、ジャンル、プレイ人数、使用エンジン | 必須 |
| 基本情報 | 対応機種 | 任意 |
| 開発期間 | 開発開始日 | 必須 |
| 開発期間 | 開発終了日 | 任意・空欄は開発中 |
| 展示 | 試遊台番号（`booth_no`） | 任意・重複可・公開ページでは非表示 |
| 表示 | テーマ | `red`・`navy`・`yellow`から選択 |
| 紹介 | キャッチコピー、作品説明 | 必須 |
| 紹介 | 見どころ、操作方法 | 任意・複数入力可 |
| 動画 | 動画URL | 任意・HTTP/HTTPSのURL |

ジャンル・対応機種・使用エンジンなどのリストは複数入力に対応する。開発日は年、年月、年月日形式を受け付け、日付の妥当性と開始・終了の前後関係を検証する。

既存のスクリーンショットデータは保持するが、この画面にスクリーンショットのアップロード・編集欄はない。旧 `production_period` は保存時に除去され、開始日・終了日を使用する。

### 5.3 プロジェクトメンバー

- 登録済み作品の編集画面に表示する。新規作品は先に作品を登録してからメンバーを追加する。
- 1作品につき最大8名。1人の学生が複数作品に参加できる。
- 学生を検索して選択し、作品内の役職を入力する。選択済みメンバーの役職は必須。
- 同じ作品内に同じ学生を重複登録できない。兼任する役職は1つの欄へ複数入力する。
- メンバーを「未選択」に戻して保存すると、その作品との所属関係を解除する。
- 非公開学生も登録できるが警告を表示する。公開ページのメンバー一覧には表示しない。
- 「メンバーを保存する」で所属情報を保存する。作品本体の保存とは別操作。
- 保存時は該当作品の紐付けを置き換え、他作品の紐付けを保持する。
- 役職は重複・空欄を除き ` / ` 区切りで保存する。該当レコードの旧 `role_group` は除去する。

### 5.4 作品QRコード

作品保存時に `team-{作品ID}` のQR管理データを同期し、有効化する。登録済み作品では固定URL、QRプレビュー、PNGダウンロード、印刷操作を表示する。

## 6. 既存の注目学生管理

- トップページに掲載する学生を追加・編集・掲載対象から削除する。
- 一覧は表示順の昇順で、件数・氏名・注目ポイント・表示順を表示する。
- 学生、表示順、注目ポイント、教員コメントをすべて必須とする。
- 表示順は1以上の整数。同じ学生の重複登録は不可。新規登録候補から登録済み学生を除く。
- 学生選択は検索に対応する。
- 削除前に確認ダイアログを表示する。削除対象は注目学生への掲載設定であり、学生プロフィールは削除しない。
- 保存・削除をJSONへ反映し、トップページの掲載データに反映する。

## 7. 既存の出展作品管理

- `teams.json` の試遊台番号が空欄でない作品を出展作品として扱う。独立した出展作品JSONは持たない。
- 出展作品の件数・作品名・チーム名・試遊台番号を表示し、試遊台番号の自然順、同番号ではID順に並べる。
- 未登録作品からチームを検索・選択し、試遊台番号を入力して登録する。
- 登録時は試遊台番号を必須とし、同じ番号を複数作品に設定できる。
- 登録済み作品の番号を変更できる。空欄で保存すると出展作品一覧から外れるが、作品本体は残る。
- 試遊台番号は作品編集画面からも変更できる。公開ページには番号を表示しない。
- 選択した作品の編集画面へ移動できる。

## 8. 追加するログイン仕様

### 8.1 合意済みの認証方式

| 利用者 | 入力する情報 | 認証後の識別 |
| --- | --- | --- |
| 管理者 | ID `admin`＋管理者用パスワード | 管理者ロール |
| 学生 | 自分の学生IDまたは氏名（漢字）＋学生用の共通パスワード | 学生ロール＋入力した学生ID |

学生用パスワードと管理者用パスワードは別に管理する。学生別のパスワード、Googleログイン、DBによるアカウント管理は今回の対象外。

学生用共通パスワードを知っている人は他の学生IDを入力してログインできる。入力したIDの学生のデータだけを編集可能にする仕様であり、実際の本人であることは保証しない。この制約は了承済み。制約の原因は共通パスワード方式であり、DBの有無ではない。

### 8.2 画面・状態管理

- `admin.php` に「IDまたは名前（テキストボックス）」「パスワード」「ログインボタン」の共通フォームを用意する。
- ID欄には学生は自分の学生IDまたは氏名（漢字）、管理者は `admin` を入力する。ログイン画面に学生名・IDの候補一覧は表示しない。
- IDの前後の空白を除去し、`admin` は管理者専用の予約IDとして扱う。パスワードの空白は変更しない。
- 数字のみの学生IDは先頭のゼロを無視し、`1`・`01`・`001`を同一IDとして照合する。保存済みIDは変更せず、セッションには該当レコードのIDを保持する。ゼロ除去後に複数レコードが一致する場合は誤認を避けてログインを拒否する。数字以外を含むIDは完全一致で照合し、一致しなければ登録氏名を照合する。氏名の半角・全角空白は無視するが、漢字の異体字変換や部分一致は行わない。氏名が複数の学生に一致する場合はログインを拒否し、学生IDでの入力を案内する。ログイン後は解決した学生IDで対象を固定する。
- 学生用パスワードの環境変数名は `TGS_STUDENT_PASSWORD` とする。ブラウザーや公開JSONには保存しない。
- 対応するパスワードが未設定の場合、その区分のログインを無効にする。
- セッションにロールと学生IDを保存する。学生ログインに既存の管理者認証フラグを流用しない。
- ログイン成功時はセッションIDを再生成し、以前のロール・学生IDを残さない。
- 学生は自分のプロフィール編集画面へ、管理者は既存の学生管理画面へ移動する。
- ログイン中の区分・学生名を表示する。別の学生として利用する場合はログアウトして再ログインする。
- 非公開学生もプロフィール準備のためログイン可能とする。学生IDが存在しなくなった場合は次回の管理画面アクセスで学生セッションを無効にする。

## 9. 追加する権限仕様

### 9.1 権限表

| 操作 | 管理者 | 学生 |
| --- | --- | --- |
| 学生プロフィールの編集 | 全学生 | ログイン時に選択した学生のみ |
| 写真の登録・変更 | 全学生 | 同上 |
| 作品情報の編集 | 全作品 | ログイン学生が参加した作品のみ |
| 参加メンバー・作品内の役職の変更 | 可 | 不可 |
| 学生・作品の新規登録 | 可 | 不可 |
| 学生・作品本体の削除 | 既存機能なし・今回追加しない | 不可 |
| 注目学生の追加・編集・掲載解除 | 可 | 不可 |
| 出展登録・試遊台番号の変更 | 可 | 不可 |
| 自分・参加作品のQR表示、PNG保存、印刷 | 可 | 既存の表示条件に従い可 |
| 学生ID・作品IDの変更 | 既存の編集機能なし | 不可 |

学生向けのタブは「自分のプロフィール」「参加作品」とする。管理者用タブ、登録・削除ボタン、メンバー保存操作は表示しない。管理者の既存機能は維持する。

### 9.2 編集対象の判定

- プロフィールはセッションの学生IDと対象学生IDの一致で許可する。
- 作品は `mapping.json` にセッションの学生IDと対象作品IDの組み合わせが存在する場合だけ許可する。
- 参加作品が複数なら、そのすべてを編集できる。同じ作品の参加学生は共通の作品情報を編集する。
- 参加作品がない場合は「参加作品は登録されていません」と表示する。
- 画面表示時と保存時に最新の所属情報を確認する。ログイン後に所属を外された作品は保存できない。
- 所属情報が読めないなど、許可を確認できない場合は更新しない。

### 9.3 項目ごとの権限

学生のプロフィール本文・基本情報・資料リンク・活動設定・写真は本人分を編集可能とする。プロフィール公開状態 `is_active` は管理者限定とし、学生の投稿では既存値を保持する。

参加作品の紹介内容・基本情報は編集可能とする。ただし、試遊台番号 `booth_no` は出展管理に直結するため管理者限定とし、学生から作品保存が送信されても既存値を保持する。作品ID、参加メンバー、役職、QR転送先の任意指定も許可しない。

学生保存時は許可した項目だけを取り込み、表示していないチェックボックスや管理者用項目を空値・falseで上書きしない。QR同期は保存対象の学生・作品に限定し、公開状態などの管理値を尊重する。

### 9.4 直接アクセス・写真への対応

- ナビゲーションの非表示だけでなく、各PHPの表示処理・更新処理でロールと対象IDを検証する。
- URL、hidden項目、POSTのID・モードを書き換えても、他学生・非参加作品の編集、登録操作、管理者専用操作はできない。
- 未認証はログインへ誘導し、認証済みで権限がない操作は既存の403エラーページへ303リダイレクトして拒否する。
- `mapping_admin.php` の旧URLは管理者専用とし、学生のアクセスは拒否する。
- 非公開の写真は「管理者、またはその写真の学生IDと一致する学生セッション」だけに許可する。学生ログインを理由に他学生の非公開写真を見せない。
- 非公開写真の権限なし・対象なしは、既存の写真配信仕様に合わせて404とする。
- 公開ページで閲覧できる他学生・作品の情報は従来どおり公開する。本仕様の編集制限は公開情報の閲覧制限とは別である。
- 権限確認はJSON更新、写真アップロード、旧写真整理、QR同期などの副作用より前に実施する。

## 10. 保存・運用上の制約

- JSONは既存の `JsonRepository` を使い、一時ファイルへの書き込み後に置き換える。PHP実行ユーザーにはデータディレクトリの書き込み権限が必要。
- 保存した内容は既存の公開条件に従って即時反映する。承認待ち・下書き・差し戻しの仕組みはない。
- 現行実装には編集履歴、復元、競合検知がない。同じ作品の同時編集では後の保存で内容が上書きされ得る。JSON全体の読み取りから置換までの排他制御もないため、異なる対象の同時保存でも更新が失われる可能性がある。
- 学生保存・写真保存・QR同期をまたぐトランザクションはなく、途中失敗時に一部だけ反映される場合がある。写真固有の失敗条件は写真仕様書に従う。
- 競合制御、履歴、個人認証の導入は本書で実装済みとは扱わず、必要に応じて別途検討する。

## 11. 実装時の受入確認項目

`node tests/admin-auth.cjs` で一時コピーとPHPテストサーバーを使い、ログイン、編集範囲、改変リクエストの拒否、保存、CSRF、非公開写真の権限、所属解除、ログアウトをHTTP検証する。実データは変更しない。Drive実接続とブラウザー上の写真操作・QR印刷は別途確認する。

| 確認内容 | 期待結果 |
| --- | --- |
| 管理者用パスワードでログイン | 既存の全管理機能が使える |
| 学生IDまたは氏名＋学生用共通パスワードでログイン | 該当学生のプロフィールと参加作品だけ編集できる |
| 誤ったパスワード・未選択・存在しない学生ID | 学生としてログインできない |
| 同姓同名の学生が存在 | 入力したIDで区別し、該当IDに固定される |
| 他学生・非参加作品のIDをURLやPOSTへ指定 | 表示・更新を拒否し、データと写真を変更しない |
| 学生が登録モード・メンバー保存・注目学生・出展管理へ直接送信 | 拒否される |
| 学生が試遊台番号などの管理者専用項目を送信 | 管理値が変更されない |
| 参加作品が0件・複数件 | 空表示または許可された全作品の一覧になる |
| 編集画面表示後、管理者が所属を解除 | その作品を保存できなくなる |
| 非公開写真へ学生としてアクセス | 自分の写真のみ取得でき、他学生の写真は404 |
| CSRF不正・ログアウト後の保存 | 更新できない |
| 管理者の既存機能の回帰確認 | 登録編集、検索、並べ替え、写真、QR、注目学生、出展作品、メンバー保存が維持される |
