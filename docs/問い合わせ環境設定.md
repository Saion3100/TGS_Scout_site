# 問い合わせフォーム 環境設定・本番テスト手順

`public/contact.php` の実装で使う設定と、本番環境での確認手順をまとめる。
設計の詳細は `docs/問い合わせ機能設計.md` を参照。

## 1. 構成

| ファイル | 役割 |
|---|---|
| `public/contact.php` | コントローラー。入力→確認→送信→完了（Post/Redirect/Get） |
| `src/contact.php` | 設定読込、入力検証、メール本文生成、3画面の描画 |
| `src/Mailer.php` | 認証付きSMTP送信クライアント（STARTTLS/587 と 暗黙TLS/465 に対応） |

Composer は使わない。`src/Mailer.php` は問い合わせフォーム専用の最小SMTPクライアントで、
プレーンテキストUTF-8メールのみを送る。ヘッダー値のCR/LFは除去するため、フォーム入力から
ヘッダーを注入できない。

## 2. 環境変数

すべて省略時のフォールバックを持つ。`TGS_SMTP_HOST` と `TGS_SMTP_PASS` の両方が
設定されるまでメールは送信されず、学校宛て通知は「送信失敗」として扱われる
（完了画面には進まない）。

| 変数 | 既定値 | 説明 |
|---|---|---|
| `TGS_SMTP_HOST` | （空） | XserverのSMTPホスト名。サーバーパネルで確認（例 `svXXXX.xserver.jp`） |
| `TGS_SMTP_PORT` | `587` | 587=STARTTLS / 465=暗黙TLS |
| `TGS_SMTP_SECURE` | `tls` | `tls`=STARTTLS、`ssl`=暗黙TLS、空=平文（非推奨） |
| `TGS_SMTP_USER` | `tgs-scout@itc.ac.jp` | SMTP認証ユーザー（通常はメールアドレス全体） |
| `TGS_SMTP_PASS` | （空） | SMTP認証パスワード。**Git・公開ディレクトリに置かない** |
| `TGS_MAIL_FROM` | `tgs-scout@itc.ac.jp` | 送信元（From）。認証ユーザーと同一にする |
| `TGS_MAIL_FROM_NAME` | `TGS SCOUT 2026 事務局` | Fromの表示名 |
| `TGS_CONTACT_RECIPIENTS` | `krc24a11@st.itc.ac.jp` | 学校宛て通知先。カンマ区切りで複数可 |
| `TGS_CONTACT_SEND_INDIVIDUALLY` | `1` | `1`=宛先ごとに個別送信（相互にアドレス非公開）、`0`=1通に列挙 |
| `TGS_CONTACT_REPLY_ESTIMATE` | `3〜5日（土日祝を除く）` | 完了画面・自動返信に載せる返信目安 |
| `TGS_CONTACT_FALLBACK` | `krc24a11@st.itc.ac.jp` | 送信失敗時などの代替連絡先として画面に表示 |

現在の設定：ポート `587` / STARTTLS、From `tgs-scout@itc.ac.jp`、通知先はデモ宛先のみ。
本番の学校指定アドレスが決まったら `TGS_CONTACT_RECIPIENTS` に追記する。

## 3. 本番での設定方法

`.env` はローカル専用で、サーバーには通常アップロードしない。本番では次のいずれかで設定する。

### A. 公開ディレクトリ外に `.env` を置く（推奨）

`src/bootstrap.php` はプロジェクト直下（`public/` の1つ上）の `.env` を読み込む。
FTP公開先が `/TGS_Scout/` で `public/` がドキュメントルートなら、`.env` は
`/TGS_Scout/.env`（Webからアクセス不可）に置ける。パーミッションは `600`。

```dotenv
TGS_SMTP_HOST=svXXXX.xserver.jp
TGS_SMTP_PORT=587
TGS_SMTP_SECURE=tls
TGS_SMTP_USER=tgs-scout@itc.ac.jp
TGS_SMTP_PASS=（サーバー管理者から受け取る）
TGS_MAIL_FROM=tgs-scout@itc.ac.jp
TGS_CONTACT_RECIPIENTS=krc24a11@st.itc.ac.jp
```

### B. `.htaccess` の `SetEnv`

公開ディレクトリの `.htaccess` に書く方法。パスワードがWebサーバーのAllowOverride設定に
依存し、設定ミスで露出しやすいので、可能なら A を使う。

```apacheconf
SetEnv TGS_SMTP_HOST "svXXXX.xserver.jp"
SetEnv TGS_SMTP_PASS "..."
```

`getenv()` は Webサーバー側で既に設定済みの値を優先する（`.env` は上書きしない）。

## 4. 事前にサーバー／学校へ確認する事項

1. XserverのSMTPホスト名・ポート（587想定）・認証情報
2. `tgs-scout@itc.ac.jp` の実在と、Fromとして送信可能なこと
3. `itc.ac.jp` のSPFにXserverの送信サーバーが含まれること、XserverでのDKIM署名可否
   （送信元ドメインと送信サーバー運営が一致しないと迷惑メール判定されやすい）
4. 1時間・1日あたりの送信数上限
5. 本番の学校宛て通知先アドレス一覧
6. PHPで `openssl` 拡張が有効なこと（STARTTLSに必要。一般的な共用サーバーは有効）

## 5. 本番テスト手順

ローカルではSMTP到達性がないため、確認と送信の直前までしかテストできない。
本番反映後に次を確認する。

1. `/contact.php` を開き、共通ナビ経由（対象なし）で送信 → 完了画面に受付番号が出る
2. 学校宛て通知が届く。件名 `[TGS SCOUT][受付番号][目的] 企業名 / 対象名`、
   本文が文字化けしない、Reply-Toが入力メールアドレスになっている
3. 入力したメールアドレスに自動返信が届く（迷惑メールフォルダも確認）
4. 学生詳細ページの「学校へ問い合わせる」→ 対象が `氏名さん` で引き継がれる（画面・メールともにIDは表示しない）
5. 作品詳細ページからも同様（`作品「タイトル」`）。内部の学生ID・チームIDは学校宛て通知メールにのみ記載される
6. 必須未入力・不正なメール形式・9文字以下のメッセージ → 送信されずエラー表示
7. `<script>` や改行を含む入力 → 画面・メールヘッダーが壊れない
8. 完了画面を再読込しても再送されない（受付番号はURLに残るが入力内容は再表示されない）
9. 確認画面で「送信」を連打しても通知メールは1通（サーバー側ワンタイムトークンで防止）
10. JavaScript無効でも入力→確認→送信できる

### メールが届かないとき

- サーバーのエラーログに `[contact] school notification failed; receipt ...` が出ていないか
  （原因の詳細はログのみに記録し、画面には出さない）
- `TGS_SMTP_HOST` / `TGS_SMTP_PASS` が空だと `SMTP not configured` を記録して失敗扱いになる
- 587で失敗する場合は `TGS_SMTP_PORT=465` / `TGS_SMTP_SECURE=ssl` を試す
